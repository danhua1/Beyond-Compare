取消后活动通道停止取新路径，尚未处理的路径直接填充取消状态；重复或无效路径仍保留错误语义。Worker 继续串行交接任务，等待已发起的读取结束后再启动替代任务，两路读取上限不变。核心进度回调数量与跨 Worker 的节流消息数量是不同指标。

页面还增加了以下处理：`pagehide` 清理任务并释放 Worker，缓存恢复的 `pageshow` 重建 Worker；自检期间禁用两个文本规则选项；输入和模式变化时清空结果引用与 DOM；路径小写键每次比较后计算一次，输入筛选以 80ms 合并，状态筛选立即应用最新查询；详情通过每侧路径索引定位文件。

## 2026-10-20：初次清单实施记录

## 文本差异计算

环境：macOS / arm64，Apple M1 Pro，Node v22.14.0。使用 `node scripts/benchmark-diff.js`，在本次改动前后同机分别启动一个 Node 进程；每种输入按固定顺序连续运行三次，不做预热。下面为三次耗时的中位数，原始样本见 [performance-results.json](performance-results.json)。

| 输入（每侧） | 修改前 / ms | 修改后 / ms | 工作量（前后相同） | 进度回调（前 → 后） |
| --- | ---: | ---: | ---: | --- |
| 相同，20,000 行 | 30.10 | 19.43 | 20,000 | 9 → 0 |
| 单行变化，1,000 行 | 0.73 | 1.73 | 1,000 | 0 → 0 |
| 完全不同，1,000 行 | 1,782.87 | 95.22 | 2,000,001 | 976 → 1 |
| 重复行，300 行 | 85.59 | 3.45 | 90,600 | 44 → 0 |
| 单行变化，20,000 行 | 26.50 | 8.51 | 20,000 | 9 → 0 |

完全不同的输入仍以 `uncompared / diff-budget` 结束，没有提高 2,000,000 工作量上限，也不返回不完整差异行。其余样本均完整成功。短任务允许不发进度，最终结果不受节流限制。

取消测量：对完全不同的 1,000 行输入，在调用前设置 5ms 定时器，回调中执行 `AbortController.abort()`；分别记录从调用到返回、从实际 abort 到返回的耗时。

- 修改前：调用到返回 5.01–7.64ms；abort 到返回 0.06–1.23ms。
- 修改后：调用到返回 4.59–6.81ms；abort 到返回 0.02–1.18ms。
- 六次均返回 `uncompared / cancelled`，无部分成功结果。

### 实现与取舍

- 每个计算单元仍精确计数并检查预算与取消；仅达到检查点时异步等待，不再每个单元分配/等待 Promise。
- 每 2,048 个工作单元检查一次是否已用时 8ms；即使用时较短，累计 32,768 单元也会让出一次。进度通知另以 75ms 控制。
- 继续使用线性空间 Hirschberg LCS，保留原始行映射、最优性和忽略规则。
- 已评估全范围替换等快速降级方案，本次不采用：把大范围变化直接标为替换可能遗漏重复行匹配并改变最优性。预算不足时继续明确显示“未比较”，不冒充完整结论。

限制：三次样本不足以构成统计性能保证，受 JIT、GC、系统调度影响；1,000 行单行变化样本反而由 0.73ms 增至 1.73ms，不能声称所有输入均提速。结果仅支持“重计算场景调度开销显著下降、这些样本取消响应未见明显恶化”，不外推浏览器或其他机器。

## Worker 进度节流

真实页面与 Worker：macOS arm64 / Chrome 150.0.7871.125。输入为 10,000 个空文件，仅左侧存在；此场景旧逻辑每文件发送一条进度，确定会发 10,000 条（非历史实测耗时基准）。

- 修改后实际收到 3 条进度消息。
- 从主线程发送任务到收到结果约 189.6ms，包含消息传输；仅作本次场景观察，不作通用吞吐基准。
- 最终统计为 10,000 个仅左侧文件，成功；结果后等待 120ms，无迟到进度。
- 进度边界采用 75ms 合并，保存最新事件；完成、取消、错误直接发送，任务替换或结束时清理待发事件。
- 1 MiB 分块通过独立 `slice` 观测验证，不依赖进度逐块到达；两路并发上限仍由核心测试验证。
